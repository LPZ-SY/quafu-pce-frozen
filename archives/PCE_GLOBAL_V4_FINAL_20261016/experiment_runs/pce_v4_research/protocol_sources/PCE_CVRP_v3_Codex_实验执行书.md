## 2. 三层输出不能混算

| 层次 | 操作 | 用途 |
|---|---|---|
| RAW原始分车 | 关联分数argmax；不跨车移动客户 | 主结果：直接分配是否可行、是否好用 |
| CAP容量约束分配 | 经典求解器根据分数和容量重分配 | 附加组：关联分数的约束落地价值 |
| FINAL统一精修 | 各输入用相同规则、预算修复并优化 | 完整混合流程的实用结果 |

分别运行RAW→FINAL和RAW→CAP→FINAL。CAP不能冒充RAW。RAW允许统一的经典车内顺序评估，但不允许跨车，所以只能称“无跨车修复”，不能称“没有经典计算”。

## 3. 新表示与解码

每个客户i、车辆k固定一个不重复Pauli观测量：

```text
scores[i,k] = <P[i,k]>
assignment[i] = argmax_k scores[i,k]
```

全部N名客户均由分数表分车。主方案不加入可自由训练的经典客户×车辆偏置表，不加入经典老师分配标签。

本轮拟采用同轴二体、三体池：

```text
pool(q) = {X_S, Y_S, Z_S : |S| in {2,3}}
pool_size(q) = 3 * (C(q,2) + C(q,3))
```

这一指定池下，8比特有252个槽位，9比特有360个槽位。30×5=150、31×5=155可用8比特；44×7=308用9比特。槽位够不等于独立自由度够，也不保证可训练、可稳定读出。

映射必须在训练前冻结，按车辆列平衡轴、阶数、物理比特使用。主映射种子20261015；敏感性追加20261016、20261017，不能看测试结果挑映射。

精确并列采用预先生成并保存种子的随机优先级表；同一输入重复解码可复现，车辆列置换时优先级也随列置换。容差1e-12。不永远选最小编号。

最少检查：旧0…7映射计数；新每客户唯一归属；全零分数无小编号偏向；车辆置换等价；Y基旋转和位序；parity与解析小状态一致。

## 4. 测量及稳定性

新实验默认一份完整分数估计为三个基合计4096 shots：X=1366、Y=1365、Z=1365。测试另外跑1024、16384两个合计档位。旧预算口径不同则另作复现，不混用。

每基先抽完整q位位串，再计算该基全部观测量的parity。保留共同shots带来的统计相关性，不用逐分数独立高斯噪声冒充真实测量。无信息读数也按各基完整均匀随机位串产生。

对同一基两个分数，其差值的采样方差：

```text
Var(s_hat_a - s_hat_b)
 = (Var(Y_a) + Var(Y_b) - 2 Cov(Y_a,Y_b)) / S_basis
```

跨基独立采样时协方差为0，方差分别按各基shots计算。可从模拟理论分布计算，或按完整shot行bootstrap；不可逐列独立bootstrap。

对参考分数第一名w_i，检查所有竞争车辆：

```text
gap[i,k] = s[i,w_i] - s[i,k]
z[i] = min_{k!=w_i} gap[i,k] / max(SE_of_difference[i,k], 1e-8)
M = mean_i max(0, 1 - z[i]/2)^2
```

目标是领先差距相对误差足够大，不是把关联值推向0或一律推向±1。阈值2只是软训练目标，不是整份分车95%稳定保证。

## 5. 四组训练与联合损失

公共任务代价：

```text
load[k] = sum_i demand[i] * 1[assignment[i]==k]
O = sum_k max(0, load[k]-capacity[k])
D_scale = (N+K) * max(distance_matrix)  # 全零距离时取1
F(a) = route_distance(a)/D_scale + lambda_cap * O/sum(demand)
```

默认lambda_cap=30。仅开发集允许预设网格10、30、100；测试集冻结。车内评估器必须确定性、预算一致，不改变分车。

每个参数候选产生参考分车a_ref及4份有限测量分车a_b：

```text
OLD_BASE:   旧取余表示；L = F(a_ref)
NEW_BASE:   新argmax表示；L = F(a_ref)
NEW_MARGIN: 新argmax表示；L = F(a_ref) + 0.1*M
NEW_JOINT:  新argmax表示；L = 0.5*F(a_ref) + 0.5*mean_b F(a_b) + 0.1*M
```

NEW_JOINT从第一步同时优化，不冻结客户分配。历史两阶段原版另记LEGACY，保留其原预算，不能冒充OLD_BASE。

所有核心组统一线路结构、参数数量、初始theta、优化器和查询预算。优先复用CMA-ES并固定版本。硬argmax与路线评价不能直接当作可微目标交给Adam；后续要做连续代理必须另命名。

不重写无依据的Hamiltonian，也不把 `<P><Q>` 默认替换成 `<PQ>`。

## 6. 规模、模型选择与预算

先运行现有约30客户/5车及44客户/7车的实际实例，不缩小。已有开发/测试划分则沿用；每规模只有1—2实例时冻结默认参数，结论限定为这些实例。重复种子和客户重排不算新实例。

默认每实例每组10个训练种子1001—1010，每run4096次参数查询。每512次保存一次截至当前训练最优checkpoint，共8个候选。每个候选用16份独立validation读出，选择顺序：

```text
原始可行率最高 → 平均超载最低 → 可行路线最短 → 客户翻车率最低 → 更早checkpoint
```

没有可行读出时，路线排序键取正无穷。冻结后每模型、每shots档用64份全新读出测试。训练、validation、test随机流互不重叠，测试不挑最好一次。

机制消融按相同参数查询数运行，并统一记录1份参考＋4份测量分配；BASE不把额外模拟分配用于训练或训练最优筛选。实用效率另跑不计算无用诊断的实现。

必须分开记账：参数查询、状态模拟/制备、逻辑候选评价、不同候选数、路线调用、模拟shots、真机shots、经典求解时间、修复时间、QPU执行与排队时间。4096参数查询、4096shots、4096候选不是同一预算。

## 9. CAP辅助实验

求二元分配x[i,k]：

```text
maximize sum_i,k scores[i,k]*x[i,k]
subject to sum_k x[i,k] = 1
           sum_i demand[i]*x[i,k] <= capacity[k]
           x[i,k] in {0,1}
```

复用现有MILP/CP-SAT，没有则采用固定版本OR-Tools CP-SAT；每次30秒、1 worker、固定种子。整数分数按1e6缩放，记录精度。不得额外加入距离目标，不拆需求，不擅自要求所有车辆非空。

四类信息输入用同一CAP求解器。默认只运行4096shots档、每模型前8个预定test批次、全部10训练种子；CAP每批只用一个预定行置换，另外19个只用于RAW归因。每实例共320次CAP求解，避免辅助求解器无限膨胀。

记录可行/最优/超时状态、时间、改动车辆的客户数及需求量。未返回可行解记失败。CAP与其他流程比较时用同一预定子集。

## 10. 经典基线与精修

必需基线：全局随机1份、全局随机256份、全局随机等预算、经典直接分车、局部随机调车。固定8客户在2车之间的局部操作另加全部256改法枚举；整个多轮局部算法不只256种方案。

经典直接算法优先现有实现；缺失时使用固定版本OR-Tools RoutingModel，容量约束，PATH_CHEAPEST_ARC初始解，GUIDED_LOCAL_SEARCH，匹配时间预算。不允许丢客户或放宽容量。

原生经典路线与公共车内评估口径分开保存，不把更好的经典原生路线换成差路线后宣称胜出。

各起点使用同一FINAL函数，冻结修复/跨车优化预算，按评价过的移动数而不是仅接受的移动数计量。分别保存RAW、仅容量修复后的REPAIR、最终FINAL。失败不能从统计中删掉。

不要求精确最优CVRP。差距对照写清楚具体经典算法和预算，不能叫最优差距。

## 13. 结论模板：根据数据选择，不预写成功

**解码改善：** 新管线车辆选择比例由[…]变为[…]，超载由[…]变为[…]，支持减轻标签偏向；这一实验尚不涉及训练信息。

**联合目标改善：** NEW_JOINT相对NEW_BASE的RAW可行率从[…]到[…]、客户翻车率从[…]到[…]；改善发生在跨车修复之前，可行路线变化为[…]。

**信息有效：** TRAINED在相同解码/后处理下优于随机参数、无信息和客户行打乱，配对效应[…]，支持分数与具体客户存在有用对应。

**真机执行有效：** 冻结参数在真机的RAW可行率[…]，同参数同shots模拟[…]，相对随机参数[…]，支持/未支持训练信息得到保留。

**仅经典处理后有效：** RAW可行性不足，CAP/FINAL后改善[…]，支持混合流程的[…]，不能归为量子直接可行。

**只有稳定性改善：** 重复读出一致性提高，但容量可行率和路线未改善，因此尚未改善求解质量。

**实用竞争力：** 在[…]预算下相对经典[…]，可行率差[…]、路程差[…]、时间差[…]。结论限于所列实例、预算和基线，不写成普遍量子优势。

## 14. 失败后怎么改

| 现象 | 下一步 |
|---|---|
| IID分数都偏车 | 修索引、并列和随机数，不继续烧真机额度 |
| IID正常，NULL_NEW偏车/超载高 | 查映射轴、阶数、支撑和客户间统计相关性，跑预定映射复验 |
| 新解码正常，仍大量超载 | 查容量/单位/罚函数及训练能否换车，再开发集调预设容量权重 |
| margin很稳但分车更差 | 降margin权重或提高shots，保留联合优化 |
| 模拟好，真机差 | 查编译、布局、读出及完整位序；统一追加shots/浅线路复验 |
| 不优于客户行打乱 | 查真实路线反馈是否有效，不把大幅度分数当客户信息 |
| 修复抹平全部差异 | 报告RAW和修复成本，不把最终收益全归量子 |
| 槽位够但差距挤不开 | 映射敏感性及对所有核心组统一加深线路，不退回局部扰动 |

完成第一轮后，按明确诊断最多做一轮改造复验，避免无限调参不交付。旧结果归档，最新冻结版本单独主表。
